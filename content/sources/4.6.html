1 · SELECT ne spremeni ničesar, DML pa takoj

Poizvedbo SELECT lahko poženeš stokrat, podatki ostanejo enaki. Stavek DML strežnik izvede in takoj trajno zapiše. Workbench ima privzeto vklopljeno samodejno potrjevanje (auto-commit), zato gumba »Razveljavi« ni. Rezultat ni Result Grid, ampak vrstica v Action Output:

UPDATE dijak SET telefon = '041 555 123' WHERE id_dijak = 3;
Action Output
#ActionMessage
1✔UPDATE dijak SET telefon = '041 555 123' WHERE id_dijak = 31 row(s) affected Rows matched: 1 Changed: 1 Warnings: 0
Kaj to pomeni: strežnik je našel eno vrstico (matched) in jo spremenil (changed). Če bi Eva ta telefon že imela, bi pisalo Changed: 0. Število v Action Output je prva kontrola, ali je stavek naredil, kar si želel.
2 · Pravilo: najprej SELECT, potem spremeni
  1. 1 · SELECTz istim WHERE, kot ga boš uporabil
  2. 2 · Preveriso to prave vrstice? koliko jih je?
  3. 3 · UPDATE / DELETEz istim WHERE (kopiraj ga)
  4. 4 · SELECTpreveri rezultat

Pogoj WHERE najprej preizkusiš s poizvedbo, ki ničesar ne pokvari. Ko vidiš prave vrstice, isti pogoj prepišeš v UPDATE ali DELETE. Tako se izogneš najpogostejši napaki: stavku, ki spremeni preveč vrstic.

3 · Safe Updates: napaka 1175

Workbench ima privzeto vklopljeno varovalo Safe Updates (Edit › Preferences › SQL Editor › Safe Updates). UPDATE in DELETE dovoli samo, če pogoj WHERE uporablja ključ (primarni ključ, UNIQUE ali tuji ključ, ker imajo vsi indeks) ali če ima stavek LIMIT. Stavek brez WHERE zavrne:

DELETE FROM izostanek;
✕Error Code: 1175Stavek je zavrnjen
You are using safe update mode and you tried to update a table without a WHERE that uses a KEY column.

Zakaj: stavek brez WHERE bi izbrisal vse izostanke. Varovalo ga ustavi, preden se kaj zgodi.

Safe Updates (preverjeno v MySQL 8.4)

Nekaterih pravilnih stavkov varovalo ne prepozna (npr. pogoj NOT IN (SELECT …) ali UPDATE s podpoizvedbo). Takrat ga za en stavek izklopiš, potem ga takoj spet vklopiš. Pred tem obvezno izvedi SELECT z istim pogojem.

SET SQL_SAFE_UPDATES = 0;   -- izklopi varovalo za to povezavo
DELETE FROM … WHERE …;       -- stavek, ki si ga preveril s SELECT
SET SQL_SAFE_UPDATES = 1;   -- takoj spet vklopi

Pozor: varovala ne izklapljaj v nastavitvah za stalno. Na maturi tega varovala ni, stavek pa mora biti vseeno pravilen: pogoj WHERE pišeš vedno, razen če res želiš spremeniti vse vrstice.

Za radovednePoskusni način s transakcijoNi v katalogu · neobvezno

Za radovedne: spremembo lahko naredimo »na poskus«. START TRANSACTION izklopi samodejno potrjevanje do konca transakcije. ROLLBACK vse spremembe od začetka prekliče, COMMIT jih potrdi.

START TRANSACTION;
DELETE FROM izostanek WHERE id_dijak = 1;
SELECT COUNT(*) FROM izostanek WHERE id_dijak = 1;   -- 0
ROLLBACK;
SELECT COUNT(*) FROM izostanek WHERE id_dijak = 1;   -- spet 2

Velja samo za stavke DML. CREATE, ALTER in DROP transakcijo samodejno potrdijo, zato jih ROLLBACK ne prekliče. Če med transakcijo zapreš povezavo, se spremembe prekličejo.
